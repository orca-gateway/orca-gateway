## 8. Risks / wire bugs
- stateKey is write-only by default. No engine class sends it, and watches come only from Values (widget.ts:155-160; json-tree-encoder.ts:156). A control bound only by stateKey writes state but does not redraw itself in Flutter. A native with local @State/remember would flip the control where Flutter does not. The working engine pattern is value: V.pageState(k) + onChange SetState(k, V.event('value')) (components.test.ts:488-521).
- Unread engine props: Checkbox inactiveColor; Radio focus/hover; CheckboxListTile/SwitchListTile drop focus/hover; IconButton splash/highlight; TFF validator. Read but never sent: stateKey (6 builders); Switch `label` (IB:252); TFF autofocus/readOnly/… (IB:98-105). isExtended is inert.
- Theme split: bare Checkbox, bare Switch and InkWell use the app theme. CheckboxListTile, Switch tile, Slider, Radio, FAB, Scaffold use ThemeData().
- Radio: with no value and no group, both strings are '' (BH:440), so every such radio draws selected. A selected disabled radio looks enabled. No ripple, 20 px target.
- Slider fires per frame. Values are doubles (50.0 vs 50 in fixtures; Kotlin JsonValue.Int vs Double). Compose `steps` = divisions − 1; SwiftUI step = (max−min)/divisions.
- InkWell's onTap is 300 ms late, always interactive, ink hidden under an opaque child.
- IconButton: no press feedback; `size` does not size an Icon child; the 40 px box is below 48.
- FAB: no handler still gives a ripple; disabled looks identical; no Hero (heroTag null).
- A Checkbox state that is not bool throws (IB:201).
- Swift writes through a SetState action; Kotlin calls store.dispatch directly (s9 decision, .pipeline/native-sdk-s9/decisions.jsonl:22).
